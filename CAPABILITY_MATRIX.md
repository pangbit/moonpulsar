# Pulsar client capability and test matrix

Compared with the public APIs of [pulsar-rs](https://github.com/streamnative/pulsar-rs)
and [pulsar-client-go](https://github.com/apache/pulsar-client-go). This is a
functional comparison, not an API-by-API claim of parity. Status reflects the
repository on 2026-09-25.

| Capability | Status | Verification |
| --- | --- | --- |
| TCP handshake, lookup, pooling, keepalive, reconnection | Implemented | Mock broker, connection refusal, malformed handshake and response, pending-request failure and release; prior real-broker restart scenario |
| Client configuration | Partial: connection/operation timeouts, keepalive, listener and lookup properties, reconnect backoff/attempts, per-broker pool sizing and idle eviction; `max_memory_bytes` charges pending producer payloads, keys, properties, encoded replay frames, incomplete chunks, queued consumer/reader messages (payload and dynamic metadata), and each inbound broker frame from its declared length through dispatch. TLS/socket internal buffers and runtime heap overhead remain outside the budget | Mock timeout, LOOKUP wire, invalid retry policy, exhausted producer/consumer reconnect, pool bound/replacement, active-handler-aware idle eviction, shared byte-budget close and encoded-frame rejection; receive queue tests cover delivery/reuse, metadata, overflow, composite forwarding/peek/stale filtering and close; chunk tests cover completion/clear/over-limit release; inbound frame tests cover pre-read admission, dispatch release, malformed-frame release, and consumer/reader error propagation without reconnect. Two-connection and expanded shared-budget live suites on 4.2.4 and isolated 3.3.9 cover producer budgeting. `examples/memory_budget` passed bounded sequential send/receive, chunk and Reader roundtrips in isolated 4.2.4 and 3.3.9 containers; the same live program verified consumer and Reader inbound-frame over-limit errors and recovery with a fresh, sufficiently budgeted client on both versions. `chunk_live_wbtest.mbt` verified consumer and Reader incomplete-chunk budget failure and release on both versions; retained-queue over-limit remains mock-verified |
| TLS service URL, CA, client certificates and protocol/cipher policy | Server-authenticated TLS and native OpenSSL 3 client-certificate authentication implemented. File identity and async identity supplier are reloaded on connection; TLS 1.2/1.3 minimum/maximum, TLS 1.2 cipher list and TLS 1.3 ciphersuites supported. macOS and Linux live mTLS verified; Windows remains unverified | TLS mock validates private CA, rejects untrusted certificate and missing key, selects TLS 1.3 cipher, rejects invalid cipher, and refreshes identity on reconnect. Isolated authenticated 4.2.4 and 3.3.9 brokers passed client-certificate send/receive on macOS and Linux; Linux runs rejected absent client cert and wrong CA and reused producer/consumer after each broker restart. Official Go RSA and Java ECIES clients exchanged encrypted messages with MoonBit over mTLS on both versions |
| Binary-protocol token and basic auth | Implemented | Token: live broker; basic: unit test; Admin REST supports bearer token |
| Auth challenge refresh | Implemented for data refresh | Handshake and post-handshake mock tests; challenge-specific algorithms remain open |
| Async auth provider and rotating token file | Implemented | Local file rotation and broker challenge mock tests; authenticated Pulsar 4.2.4 rejected an invalid rotated file token, then accepted a second valid token on a new connection from the same client and completed send/receive. | Producer send, async receipt, batching, compression, delayed delivery | Implemented, including CRC32-C on outgoing SEND frames and spec-compliant batch payloads | Mock broker and live broker scenarios; official Go client decodes MoonBit-produced Protobuf Native, INT64 and two-message STRING batch payloads on 4.2.4 |
| Producer pending queue and send timeout | Per-producer pending-message limit and client-wide retained-message and encoded-frame byte limit shared with receive queues and incomplete chunks. Admission can block for the message; encoded-frame admission fails immediately if both retained copies cannot fit, avoiding a wait while holding the original reservation. Buffered batch messages time out from admission and are removed before flush. Full heap-memory accounting remains open | Mock cross-producer full/block/release, timeout recovery, close wakeup, metadata and frame rejection, pre-flush and in-flight timeout, late and early receipts, batch removal, send failure and invalid options; expanded shared-budget, batch expiry followed by successful flush and bounded sequential sends passed on 4.2.4 and isolated 3.3.9 |
| Producer access modes, metadata, reconnect epoch, and last confirmed sequence | Implemented | Mock wire, broker-history sequence, wait-ready, and reconnect tests; live exclusive conflict and wait-for-exclusive takeover |
| Producer chunking and compressed chunking | Explicit or broker-limit-driven automatic chunking implemented; chunk `SEND` frames set `is_chunk=true`, and oversize frames fail before write | Wire-size, `is_chunk` flag and failure-path mocks; 6 MiB auto-chunk roundtrip and `examples/memory_budget` chunk roundtrip on isolated Pulsar 4.2.4 and 3.3.9 |
| Partition routing and producer expansion | Key hash, round-robin, single-partition, and custom callback routing implemented for initially partitioned topics, including one-partition topics | Mock routing and invalid-index tests, one-to-two and live two-to-three partition expansion; custom routing on 4.2.4 and 3.3.9 |
| Single, partitioned, and explicit multi-topic consumption | Implemented; initially partitioned consumers discover added partitions | Mock one-to-two expansion and bounded slow-consumer forwarding; live two-to-three expansion |
| KeyShared auto-split and sticky hash ranges | Implemented | Range validation and SUBSCRIBE wire mock; sticky policy live broker |
| Pattern subscriptions | Topic additions and removals implemented; a broker `CLOSE_CONSUMER` on a pattern source defers recreation to the next namespace discovery | Mock addition, removal, stale-queue filtering, broker-initiated close without premature re-subscription, and re-addition; isolated 4.2.4 and 3.3.9 live runs deleted active non-partitioned and two-partition topics, observed source removal, recreated each topic and received again |
| Consumer options, ack/nack, ack timeout, seek, unsubscribe | ACK can optionally await a broker response; opt-in batch-index ACK and default whole-batch ACK implemented. Transactional ACK supports both batch modes, registering the subscription and confirming each wire ACK. Optional ACK grouping buffers by count/time, coalesces cumulative positions, flushes on close/seek and bypasses grouping for confirmed ACKs. Zero-sized on-demand receive queue is limited to non-partitioned single-topic consumers, with explicit errors for composite subscriptions; opt-in auto-scaled receive queue implemented for single-topic consumers; the latter is propagated to composite subscriptions. Composite consumers still prefetch into their merge queue. ID-list ACK combines ordinary IDs in one frame and preserves batch-index handling; per-topic last-message IDs are available | Mock grouped frames, timer/close flush, confirmed ordering, batch bitmaps, cumulative coalescing, reconnect drop/retry and invalid options; grouped ACK persistence on 4.2.4 and 3.3.9. Mock batch ACK bitmaps (including 65 indexes), single-message batch for consumer/reader, broker ACK-set filtering, rejected ACK retry and transactional distinct-index bitmap retry; whole-batch and per-index ACK with consumer reopen on both versions (`acknowledgmentAtBatchIndexLevelEnabled=true`); transactional whole-batch and per-index ACK rollback redelivery and commit persistence on 4.2.4 and isolated 3.3.9; official Go two-message INT64 batch decoded by MoonBit on 4.2.4; mock auto-scale FLOW growth/bound/reset; zero-queue and auto-scale receive, ack timeout and ID seek on both versions; new mock checks reject partitioned and composite zero queues, verify one-frame ID-list ACK with rejection/retry, and query last IDs for each composite source with malformed-response recovery; 4.2.4 and isolated 3.3.9 live suites verified composite last IDs and confirmed ID-list ACK |
| Exponential negative-ack backoff | Implemented for `Message::nack` | Timing and close-cancellation mock tests; live broker redelivery |
| Chunk reassembly and ACK | Implemented with bounded memory and configurable expiry/pending count; incomplete chunks charge the shared client byte budget, and budget exhaustion closes the affected consumer/reader queue with `ClientMemoryFull`; `ChunkAssemblyPolicy::new(auto_ack_incomplete=true)` ACKs received IDs of evicted incomplete chunks, default false | Mock wire, capacity eviction, periodic expiry, optional ACK and default no-ACK tests for consumer/reader; shared-budget failure and release on complete/clear/discard for both receiver types. Complete-chunk consumer/reader replay passed live. `scripts/test-chunk-live.sh` injects incomplete broker messages and verifies consumer and Reader buffer expiry, broker cursor advancement and subsequent receipt, then verifies `ClientMemoryFull` and released budget after two chunks for both receiver types on isolated 4.2.4 and 3.3.9 |
| Reader, seek, replay, and added-partition discovery | Implemented for initially partitioned topics; custom name/properties/subscription, last-message ID per partition, inclusive start and seek | Mock inclusive/exclusive and empty-latest paths, one-to-two expansion, SUBSCRIBE metadata, invalid name, malformed SUBSCRIBE and last-ID replies with handler cleanup, bounded slow-reader forwarding, chunk expiry, and disconnect wakeup; live explicit/latest inclusive on 4.2.4 and 3.3.9, two-to-three expansion; 4.2.4 and isolated 3.3.9 live single-topic last-ID maps |
| Transaction coordinator lookup and transaction lifecycle | Implemented; participant registration checks broker response type and errors, and transactional batch ACK confirms each sent ACK | Mock lifecycle, rejected/malformed coordinator attach, begin/end and participant replies, transactional batch-index registration and rejected-ACK retry; live coordinator/abort and producer/subscription participant registration on 4.2.4 and transaction-enabled isolated 3.3.9; transactional whole-batch and per-index commit/rollback on both versions |
| Admin topic and subscription operations | Selected endpoints implemented, including partitioned-topic list/stats, topic properties, and subscription create/skip/expire | Mock HTTP path, body, JSON-shape, and invalid-input tests; live create/expand/query/stats/delete, topic property updates, and subscription cursor/backlog behavior |
| Schema declaration, versions, and typed payload conversion | STRING, JSON, BYTES, integer/float primitives, Avro datum and typed mapping, Protobuf Native, and legacy Protobuf codecs; broker schema/version lookup and message version propagation implemented. INT16/32/64 default to Java-compatible big-endian encoding and accept `little_endian=true` for Go-client encoding. Async `Client::decode_avro` fetches and caches writer schemas by message topic/version, then resolves field aliases/defaults, unions, collections, enum fallbacks and allowed numeric promotions; incompatible schemas return `SchemaIncompatible` | Local wire-byte, range, malformed-payload, endian, Avro schema/datum validation, descriptor validation, GET_SCHEMA error and version tests; STRING, JSON, INT64, Protobuf Native and schema-version broker roundtrips on 4.2.4 and 3.3.9. Pinned official Go client and MoonBit exchanged Avro records, Protobuf Native, legacy Protobuf, INT8/16/32/64, FLOAT, DOUBLE, and BYTES values in both directions on 4.2.4 and 3.3.9. Mock Avro evolution covers normal, incompatible, failed lookup/retry and cached reuse; official Go v1 writer to MoonBit v2 reader passed on 4.2.4 and isolated 3.3.9. The pinned Go reader cannot fill a v2 default field from v1 bytes (`interop/go/avro_evolution_test.go` expects its EOF), so that reverse evolution case is a reference-client limitation; Official Java v1 writer to MoonBit v2 reader and MoonBit v1 writer to Java v2 reader passed on isolated 4.2.4 and 3.3.9; both directions verified field alias, default value and int-to-long promotion |
| Dead-letter policy | Implemented for consumer delivery and negative ack; producer created when the consumer is created | Mock publish-before-ACK, send-failure NACK, direct consumer NACK, composite non-blocking receive, and live broker explicit-NACK routing (including a broker that reports redelivery count zero) |

| Producer and consumer interceptors, events, tracing, metrics | Producer and consumer hooks implemented. `ClientOptions::new(on_event=...)` reports structured send, receive/try-receive success and failure, ACK/nack and producer/consumer reconnect events; `ClientMetrics` counts outcomes including receive and negative-ACK failures. `moon test --target native` runs the in-process mock suite. The
`examples/live_capabilities` program exercises an authenticated Pulsar broker;
set `PULSAR_ADMIN_URL` to include Admin REST checks. The live program is not
part of `moon test` and requires a broker. `moon coverage` measures mock-suite
line execution and therefore does not include the live program's execution.
The mock suite does not yet reach full library line coverage; uncovered paths
include additional connection failure paths and several existing
reader/transaction branches. Malformed frame lengths and missing handshake
metadata now have executable regression tests.
