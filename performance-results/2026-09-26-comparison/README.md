# 三客户端真实 Broker 性能对照（2026-09-26）

已完成四种 1 KiB 场景，共 36 组正式对照及 6 组冒烟测试。64 KiB 场景因 Broker 堆外内存耗尽而中断，未形成完整对照，不纳入下表。

版本：MoonPulsar `3227d9a`；[Apache pulsar-client-go](https://github.com/apache/pulsar-client-go/tree/a83c1519f68dfdbddfa7955a56d91735bd1ca95c) `a83c151`；[StreamNative pulsar-rs](https://github.com/streamnative/pulsar-rs/tree/929bc549b2130d1e49e16bac0a652be59d483c7d) `929bc54`。通过本仓库适配程序使用原版客户端执行相同负载，不是直接比较各项目默认压测工具。

环境与口径：Pulsar 4.2.4 standalone；Linux x86_64，共享虚拟机 24 vCPU / 16 GiB；客户端与 Broker 同机，Token 认证，无 TLS、无压缩。每个生产者、消费者进程分别固定到一个 vCPU；Go `GOMAXPROCS=1`、Rust 单线程 Tokio、MoonBit native release。工具链为 Go 1.26.5、Rust 1.94.0、moonc 0.10.14。

每个场景三轮，轮换客户端顺序。生产者预热 3 秒、测量 10 秒；消费者提前 2 秒启动，预热 7 秒、测量 7 秒。每个工作任务最多一个未确认发送；接收队列 1000，batch 上限 128 KiB、等待 1 ms。吞吐为三轮均值，括号为最小–最大值；P99 为三轮发送确认延迟 P99 的中位数，直方图粒度 100 μs；RSS 为三轮生产者进程峰值的最大值。

本轮单并发差异很小；32 并发关闭 batch 时 MoonPulsar 吞吐最高，但生产者内存明显偏高。batch=100 时 Go 最快，batch=32 时 Rust 最快；不存在所有场景均领先的客户端。32 并发无法凑满 100 条 batch，客户端的定时器及批处理实现差异会影响结果。

64 KiB 测试中，MoonPulsar 第一轮正常完成，随后 Go 第一轮期间 Broker 达到 4 GiB 堆外内存上限并退出，Go 收发均失败，其余七组未执行。日志确认是 Broker 资源故障，不能据此判定 Go 客户端缺陷；该场景的成功片段也不用于排名。失败 Topic 尚待服务恢复后清理，完整三轮对照待补测。

这些是共享环境短时测试结果，不代表生产容量或长期稳定性。消费者吞吐受供给限制；收发窗口不同，不能由两列差值推算丢失率；P99 不是端到端延迟。
