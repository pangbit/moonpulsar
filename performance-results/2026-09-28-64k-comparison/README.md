# 64 KiB 三客户端性能对照（2026-09-28）

三种客户端各三轮，共九组正式测试全部完成；18 个收发进程正常退出，标准错误为空，发送延迟直方图无溢出，九个专用 Topic 均删除成功。补齐了[上一轮](../2026-09-26-rss-broker-rerun/README.md)因 Broker 故障未完成的 64 KiB 对照。

版本：MoonPulsar `8b4eeb6` 对应的 RSS 修复实现；Go 客户端 `a83c151`；Rust 客户端 `929bc54`。复用上一轮三个 Linux release 二进制并核对 SHA-256，未重新构建或改动客户端。MoonPulsar 二进制 SHA-256 为 `c99f5fcb2b072d4c5548424ce2e0cb74702b71dcb553bfae310663b4a3c0e71d`。

环境：Pulsar 4.2.4 standalone，共享 Linux x86_64 虚拟机，24 vCPU / 16 GiB。客户端与 Broker 同机，Token 认证，无 TLS、无压缩；每个生产者、消费者进程分别固定一个 vCPU，Go `GOMAXPROCS=1`，Rust 单线程 Tokio，MoonBit native release。本轮开始时 Broker 已运行，整个矩阵未执行重启或配置调整。

负载：64 KiB payload，32 个发送工作任务，每个任务最多一个未确认发送；不限速，batch 最多 100 条、最多 128 KiB、等待 1 ms；队列 1000，超时 10 秒。每个新 Topic 先用对应客户端以 100 msg/s 预发送 1 秒，再用独立消费者实际读取，要求消息数大于零且进程正常退出后才进入正式测试。就绪检查不计入正式测量。

正式生产者预热 3 秒、测量 10 秒；消费者提前 2 秒启动，预热 7 秒、测量 7 秒。每组使用新 Topic，三轮轮换顺序为 Go→Rust→MoonPulsar、Rust→MoonPulsar→Go、MoonPulsar→Go→Rust。吞吐为三轮均值及最小–最大范围；P99 为三轮发送确认延迟 P99 的中位数，直方图粒度 100 μs；RSS 为三轮进程峰值的最大值。

该负载下 Go 吞吐最高，MoonPulsar 次之；MoonPulsar 的生产者峰值 RSS 与 Rust 接近、低于 Go。三者以不同吞吐运行，P99 不能解读为相同请求速率下的延迟对比。Go 的逐轮吞吐波动较大，说明共享环境短时结果不宜用作固定容量承诺。64 KiB 消息会优先受到 128 KiB batch 字节上限约束，配置 100 条不代表实际每批 100 条。

本轮未重现此前的堆外内存耗尽或零消费失败，但不能据此认定 Broker 根因已修复。消费者吞吐受供给限制；收发窗口不同，不能从计数差推算丢失率。P99 是发送确认延迟，不是端到端延迟。Rust 适配层等待超时与库内部 operation timeout 不完全等价。本次是补充性能测试，未修改客户端代码，未重复运行此前通过的 323 项功能回归。
