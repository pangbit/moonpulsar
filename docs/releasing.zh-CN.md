# 发布流程

[English](releasing.md) | 简体中文

Mooncakes 发布由维护者手动执行。准备候选包、提交、推送、创建 GitHub Release 和执行 `moon publish` 是独立步骤；本流程不自动执行任何发布操作。

## 发布前

1. 确定版本，核对 `moon.mod`、示例依赖和 CI 中候选 ZIP 文件名。在冻结候选提交前，完成 CHANGELOG 版本、计划发布日期及中英文 README 的安装说明。将临时的“尚未发布”文字改为该版本的安装说明，并提示读者核实注册表可用性；实际发布成功前不能宣称已发布。若发布日期变化，需生成并验证新的候选提交。
2. 按[开发与验证说明](testing.zh-CN.md) 完成本地验证和包内链接检查。检查 `moon package --list` 的内容；测试夹具、历史报告、互通程序和脚本不应进入库包。
3. 完成经过审核的提交和推送，确认远端提交与候选源码一致、该提交的所有必需 CI 作业通过。历史通过记录不能替代这次结果。
4. 从候选 ZIP 构建外部消费者，验证依赖解析和 native 编译；确认已记录的平台与 Broker 验证边界。
5. 检查 GitHub 在线文档链接的目标已随提交到达远端。链接检查脚本只检查对应的本地目标，不验证远端页面可访问性或 Markdown 锚点。

## 维护者执行发布

在确认的干净候选提交上，先检查账号与版本：

```sh
moon whoami
moon view pangbit/moonpulsar --versions --json
```

查询返回 404 不单独证明账号有发布权限或版本可用。确认后，由维护者执行：

```sh
moon publish
```

发布成功后重新查询版本，在仓库外的新建消费者中通过注册表安装并构建。在经过验证的确切候选提交上创建对应 GitHub tag 和 Release，并在 Release 说明中记录发布结果。不要把发布标签移到后续文档提交；后续文档修正使用独立提交，不会改变已发布的包。发布包、注册表版本与 GitHub Release 必须追溯到同一候选提交。
