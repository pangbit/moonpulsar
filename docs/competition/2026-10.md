## October contribution

- Repair ordinary-TLS transport ownership and isolate ECIES adapter errors on
  the documented runtime combinations.
- Drain sends admitted during producer replay, honor close during reconnection,
  and bound admission/writes/keepalive by the existing deadlines.
- Improve portable CRC32-C, retain relay/TCP regressions, and pin the verified SDK.

The public API and dependency versions stay unchanged. The
[existing contribution table](https://github.com/pangbit/moonpulsar/blob/v0.1.2/docs/verification-0.1.2.md#october-contributions)

## Exact install and minimal demo

Use `moon`/`moonrun` 0.1.20260920 (`914d7da`) and `moonc` 0.10.14+7d59c7ec9.
A separate native application declares `"pangbit/moonpulsar@0.1.2"` and
`"moonbitlang/async@0.22.1"` in `moon.mod`; the
[tagged installation guide](https://github.com/pangbit/moonpulsar/blob/v0.1.2/README.mbt.md#installation)
contains the package imports and client code. Query the exact release with:

```sh
moon view pangbit/moonpulsar@0.1.2 --json
```

For the existing source demo:

```sh
git clone --branch v0.1.2 --depth 1 https://github.com/pangbit/moonpulsar.git
cd moonpulsar
moon update
```

Start a fresh local Pulsar 4.2.4 standalone using the tagged guide above and wait
until its namespace query succeeds and includes `public/default`. Then run:

```sh
moon run examples/roundtrip --target native
```

Expected output: ten checked `verified:` lines, then `roundtrip OK`; the client
closes normally. Stop the disposable Broker as described in the guide. This
ordinary example checks payload roundtrip and does not inject a Writer fault.

## Recorded behavior and limits

On the unchanged product snapshot `832b431`, an isolated Pulsar 4.2.4 run completed
10 sends, 10 matching receives and 10 Broker-confirmed ACKs. A separate live
Writer case withheld A's genuine old receipt, retained its original future,
reconnected the client transport, paused the actual replay Writer after one byte,
and admitted B. Releasing the checkpoint completed both original receipt futures.
Initial A, replay A and B were received and individually ACK-confirmed; both runs
exited naturally and cleanup was independently confirmed. See the
[source-bound evidence and runtime limits](https://github.com/pangbit/moonpulsar/blob/v0.1.2/docs/verification-0.1.2.md#live-verification-on-2026-10-29).

The Writer case kept the same Broker running. Retaining one unconfirmed SEND's
original future across a Broker restart remains **unverified and deferred**.
Duplicate delivery is possible; no exactly-once, deduplication or recovery-SLA
guarantee is established. TLS/ECIES and historical interoperability results keep
their documented source/runtime boundaries. The CI above applies to release
`a207860`, not to later documentation commits.
